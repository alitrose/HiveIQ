Beekeeper Screening Heuristics
Advisory Standards

1. Temperature Sensitivity: Honeybee brood must be held strictly between 33°C and 36°C. If internal hive temperature drops below 32°C, larvae suffer from hypothermic chilling. Above 37°C, comb waxes soften and brood mortality rises.

Note on Demo Sensor Data: The default inspection logs displayed here are simulated records to demonstrate offline persistence and screening rules. In real deployment, IoT thermistors would transmit these automatically.

2. Humidity & Fungal Pathogens: Readings exceeding 68% relative humidity encourage Ascosphaera apis (Chalkbrood disease) and Nosema spore propagation. Ventilation must be increased.

3. Varroa Mite Screening: Any visual detection warrants immediate sticky board sampling or oxalic acid vapor screening before honey supers are filled.

Key Viva Explanations (Defending Model Performance Honestly):
  • Why is the Regression R² 0.9801? Country honey production exhibits high temporal autocorrelation (inertia). A country producing ~70,000 tonnes does not suddenly produce 200 tonnes next year without catastrophic collapse. The lag-based features capture this baseline effectively.
  • Why is Classification Accuracy 61.2%? Agricultural year-over-year growth is subject to subtle climate fluctuations (rainfall, spring nectar flow, colony mortality) which cannot be completely captured by macroeconomic production totals alone.
  • Why Time-Aware Split? A random K-Fold split would cause data leakage (using 2023 data to predict 2021). The chronological split (1964-2014 train, 2015-2024 test) strictly mimics real-world forward forecasting.

23CS2024 Course Guide

1. Project Overview & Pitch (for Examiner)

"HiveIQ is an end-to-end data science application combining global macro honey production analytics from the UN FAOSTAT dataset (9,601 records, 1961-2024) with local hive health tracking and machine learning models. We implemented Linear Regression, Logistic Regression, KNN, and K-Means Clustering in Google Colab, validated them using a chronological train/test split, and exported the parameters to this standalone web application."

3. Frequently Asked Viva Questions & Answers

Q1: Why did you choose Linear Regression over KNN for the primary regression model?

A: On our held-out test data (2015-2024), Linear Regression achieved an MAE of 2,350 tonnes versus 2,896 tonnes for KNN, and an R² of 0.9801 vs 0.9643. Linear Regression is also computationally O(1) in the browser, making it ideal for client-side JavaScript execution.

Q2: Why is the Logistic Regression recall so high compared to its precision?

A: With a slight positive bias in the historical data (55.8% of years showed production increases), the model reliably catches almost all growth years (recall 98.9%), but tends to be slightly optimistic on borderline flat years, resulting in 60.8% precision.

Q3: How are predictions calculated in the browser without a Python server?

A: We exported the exact standardization weights, coefficients, intercepts, and cluster centroids from Colab into model.json. JavaScript multiplies the normalized user inputs with these weights directly inside the client's browser.
